## Старт для всех (15 минут)

```bash
git pull
./setup.sh                 # Windows: setup.bat   (нужен Python 3.13)
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python scripts/fetch_data.py --sample-input 3
python -m evaluation.run_eval --mode rules     # должно показать F1 ≈ 0.18 — это наша точка отсчёта
pytest -q                                      # всё зелёное, 43 теста "skipped" = ещё не реализовано
```

**Правила:**
- Своя ветка `feat/<имя>-<что>`, маленькие PR в `master`. Перед PR: `pytest -q`, `ruff check .`, `python -m evaluation.run_eval`. В описании PR — **F1 до → после**.
- Не трогаем чужие файлы без договорённости. Общие файлы (`spec.py`, `models.py`, `pipeline.py`) меняем только через меня.
- **Работа с веб-LLM:** вставляете в чат (1) свой файл целиком, (2) тесты к нему, (3) нужный YAML из `config/doc_types/`, (4) фразу «реализуй TODO, не меняй сигнатуры функций». Результат → `pytest` → PR.
- Отладка: `python -m odwolania2json inspect файл.pdf` (текст страниц), `... classify файл.pdf` (баллы классов). Ошибки по полям — в `runs/<время>/report.json` → раздел `errors`.

## Сева — PDF, OCR, сканы, Docker

1. Поставить Tesseract (`brew install tesseract tesseract-lang`) и проверить на реальном скане: `python -m odwolania2json inspect "input/szablon_case1/przyklad odwolanie.pdf"`. Сравнить с RapidOCR (`OCR_ENGINE=rapidocr`).
2. `odwolania2json/ingest/ocr.py`: предобработка картинки (выравнивание наклона, бинаризация), **слова с координатами из OCR** → `Page.words` (нужно для подсветки в панели), уверенность OCR по странице.
3. `odwolania2json/ingest/pdf.py`: склейка переносов («postępo-\nwania»), артефакты выравнивания по ширине, «мусорный» текстовый слой → OCR.
4. `scripts/make_scans.py`: функция `degrade()` (наклон ±1.5°, шум, размытие, JPEG, серый фон, чёрные плашки как в анонимизированном примере) → `python -m evaluation.run_eval --data data/scans/dane`. **Это наш замер качества на «реальных» документах.**
5. Кэш ingest (`.cache/ingest/<hash>.json`), чтобы OCR не гонялся заново при каждом eval.
6. Docker: собрать образ, проверить `docker compose run --rm app` и `docker compose up web` (нужно для приза).

**Готово, когда:** F1 на синтетических сканах не более чем на 10 п.п. ниже, чем на текстовых PDF.

## Лёша — правила и regex-экстракция, анализ ошибок

1. `odwolania2json/extract/rules.py` — по порядку из TODO в файле, после каждого шага прогон eval:
   1. `labels` — «Метка: значение» или значение на следующей строке (поможет в przelew сразу на все 6 полей);
   2. `section` — поиск дочерних полей только внутри блока (Odwołujący ≠ Zamawiający, у обоих есть NIP!);
   3. списки + `item_split` — 2 заказчика, консорциумы, несколько pełnomocników;
   4. эвристики (например, `nazwa` = первая строка секции).
2. Дописывать `labels`/`patterns` в `config/doc_types/*.yaml` по ошибкам из `report.json`. **Код должен оставаться универсальным** — всё специфичное для класса живёт в YAML.
3. Анализ `czynnosc_powod_id` на 60 делах: какие формулировки первого zarzutu ведут к какому id → `keywords` и `hint` в `config/dictionaries/czynnosc_powod.yaml`.
4. Таблица «поле → F1 → почему ошибки» после каждого большого изменения (кидать в чат команды).

**Готово, когда:** в режиме `rules` F1 > 0.7 на обучающем наборе.

## Артём — нормализаторы, панель (веб-UI), документация

1. **Первые 1–2 часа: нормализаторы и валидаторы** — самый быстрый прирост F1.
   - `odwolania2json/normalize/values.py` (`date_pl`, `amount_pl`, `account_number`, `bzp`, `ted`), `normalize/text.py` (`strip_quotes`, `email`, `person_name`), `validate/checksums.py`.
   - Спецификация — докстринги + `tests/test_normalizers.py`, `tests/test_validators.py`. Реализовал функцию → её тесты из «skipped» стали зелёными.
   - Одна только `date_pl` даёт +45 верных полей. Проверка: `python -m evaluation.run_eval --mode rules`.
2. **Панель (веб-UI)** — `web/` (сейчас там рабочая заглушка). Чистые HTML + CSS + JS, без сборки. Библиотеки кладём локально в `web/vendor/`: on-premise без интернета!
   - загрузка нескольких PDF (drag & drop), список документов с типом и уверенностью;
   - итоговый JSON (подсветка синтаксиса, кнопка «скачать»);
   - **просмотр PDF (PDF.js) с подсветкой, откуда взято каждое поле**: клик по полю → страница и фрагмент. Данные: `fields[].evidence {page, snippet, bbox}`;
   - значки метода (regex / LLM) и уверенности → это наша «прозрачность» для жюри;
   - светлая и тёмная тема, нормальный вид на ноутбуке и проекторе.
   - API и формат ответа: `odwolania2json/api/app.py` (докстринг вверху). Запуск: `./start.sh web` → http://localhost:8000
3. **Документация:** `docs/NOWA_KLASA_DOKUMENTU.md` (пример по шагам), `docs/ARCHITEKTURA.md`, польский README — ближе к концу.
4. **Презентация** (вместе со мной): проблема → архитектура → F1 → живое демо (добавить новый класс YAML за 5 минут).

**Готово, когда:** панель показывает загрузку → JSON → подсветку источника; все тесты нормализаторов зелёные.
